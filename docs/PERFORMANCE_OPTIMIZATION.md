# GAM パフォーマンス最適化ガイド

## まず確認すること

大量のAddonを初めて読み込むときは、Workshopメタデータとサムネイルの補完に時間がかかります。GAMは画面に必要な項目から段階的に処理するため、起動直後や大きくスクロールした直後は少し待ってください。

1. SteamのAddonダウンロードが完了していることを確認する
2. GAMの更新ボタンを1回押し、完了表示を待つ
3. 名前・状態・Type/Tagなど不要なフィルターが残っていないか確認する
4. ネットワーク取得が必要な画像では、インターネット接続を確認する

更新ボタンを短時間に連打しても処理は速くなりません。GMod実行中に状態を変更した場合、実状態への適用はGMod終了後まで保留されます。

## サムネイルキャッシュ

GAMは次の順でWorkshop画像を探します。

1. GAMのローカルicon cache
2. Garry's ModのWorkshop cache
3. Steam libraryのpreview cache
4. Steam側から取得したpreview URL

GAMのローカルicon cacheは次の場所です。

```text
%APPDATA%\GmodAddonManager\icons
```

現在の購読集合で使われているiconは保持します。購読集合にないiconは、GAMが最後に確認した時点から30日以上経過した場合に起動時の整理対象になります。

### cacheを手動で作り直す

画像が壊れている、または古い画像から更新されない場合だけ、次の手順を使います。

1. GAMを終了する
2. `%APPDATA%\GmodAddonManager\icons` を別名へ変更する
3. GAMを起動し、画像が再取得されることを確認する
4. 問題がなければ、退避した旧フォルダーを削除する

`config.json` や `settings.json` はAsset構成とUI設定なので、cache整理の対象にしないでください。

## セキュリティソフトについて

Windows Defenderや他のセキュリティソフトがファイルアクセスを検査することはありますが、GAMはDefender除外の追加を推奨しません。cacheフォルダーを除外すると、その場所へ保存されたファイルの検査も無効になるためです。

セキュリティソフトが原因と疑われる場合は、保護を無効化せず、Windows セキュリティの「保護の履歴」や利用中の製品ログでGAMのファイルが実際にblockされているか確認してください。再現時刻と `%APPDATA%\GmodAddonManager\logs` を添えて報告すると原因を切り分けやすくなります。

## トラブルシューティング

### 画像が表示されない場合

1. 対象AddonのWorkshopページにpreview画像があるか確認する
2. GAMの更新完了後も表示されないか確認する
3. `%APPDATA%\GmodAddonManager\icons` へ現在のWindowsユーザーが書き込めるか確認する
4. 上記の手順でicon cacheを退避して再生成する
5. `%APPDATA%\GmodAddonManager\logs` の同時刻のerrorを確認する

Steamクライアントの管理者起動やGAMの管理者起動は必要ありません。通常ユーザーで書き込めない場合は、権限を昇格して回避するのではなく、GAMの保存先権限やセキュリティソフトのblockを修正してください。

### 一覧操作が重い場合

- 検索や状態フィルターで表示件数を絞る
- 初回メタデータ補完と画像取得が終わるまで待つ
- Steamのダウンロード中は完了後に更新する
- 同じ症状が再現する場合は、Addon件数、選択中Asset、並び替え条件、再現手順とログを記録する

## 実装上の要点

- Workshop一覧のscan結果は短時間cacheされ、重複scanを抑えます
- 画像は画面上で必要な範囲を優先して非同期読込します
- network画像は同時実行数を制限し、応答サイズを上限付きで読み込みます
- 使用されなくなったicon cacheは30日基準で段階的に整理します

内部の並列数やcache方式はversionごとに調整されるため、固定値をユーザー設定として変更する機能はありません。
