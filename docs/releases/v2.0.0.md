# GAM v2.0.0

GAM 2.0.0 is a rebuilt private validation release. It combines the Asset,
Asset Group, Smart Asset, `.gam` sharing, subscription-state, sorting, and UI
work completed during the v2 development cycle into one supported baseline.

## Main changes

- Asset Groups can contain Assets and nested Asset Groups. Group state is
  inherited by newly created children, and hierarchy depth remains bounded by
  the configured limit.
- The Asset picker follows the same hierarchy as the main Asset list instead
  of flattening every nested Asset into one long list.
- Smart Assets can derive membership from GAM's addon type and Workshop tag
  metadata and refresh on startup or manual refresh.
- `Subscribe Asset` and `GMod Disabled Addons` are fixed system Assets. Newly
  discovered subscriptions inherit the current Subscribe Asset state, while
  GMod-disabled addons remain represented separately.
- `.gam` Bundle v4 can preserve multiple Assets, nested groups, states, memos,
  and optional compressed images without changing Steam subscriptions.
- Addon images, Workshop names, subscription timestamps, chronological sorting,
  split-window layouts, and group navigation have been corrected and polished.
- Experimental local-addon display and Asset history remain disabled by
  default.

## Reliability and security hardening

- Legacy v1 hard-layout data is detected before normal startup and recovered
  through a journaled, validated migration path rather than deleting or
  overwriting Workshop payloads in place.
- `.gam` archives and `addon.json` metadata now have technical resource bounds,
  path validation, cancellation support, and fail-closed malformed-input
  handling.
- Standard GMA v0-v3 headers and numbered file tables are parsed according to
  the official `gmad` layout, including required-content lists and
  classification metadata stored in the header description. Later entries are
  no longer silently skipped.
- Path-health migration accepts data only from the exact legacy GAM managed
  root and revalidates every source and target before moving it. A damaged or
  edited configuration cannot nominate a Steam Workshop or GMod payload root
  as GAM-managed data.
- Deferred GMod runtime changes are persisted even when startup discovers a
  membership change before the runtime queue has finished initializing.
- Update downloads require HTTPS, an expected GitHub asset origin where
  credentials are used, a bounded response/download size, and a valid SHA-256
  digest. Portable builds receive a portable-only marker and no longer install
  a second per-user copy while updating.
- GitHub Actions are pinned to reviewed commit SHAs, NuGet restores use checked
  lock files and fail on vulnerability advisories, and release tags must be an
  annotated exact SemVer tag pointing at `origin/main`.
- The installer remains per-user (`PrivilegesRequired=lowest`) and no longer
  downloads or launches the unnecessary Visual C++ Redistributable. Upgrades
  remove only obsolete files listed by the previous managed release manifest;
  user data under `%APPDATA%` is never recursively deleted.
- Setup blocks an exact detected all-users GAM 1.x installation, or a previous
  per-user GAM installation that predates the managed release manifest, and
  asks the user to uninstall it first. Setup never silently launches or removes
  the old installation. This prevents an old v1 executable from recreating the
  legacy Workshop layout after migration.

## Files

- `GAM-Setup-2.0.0.exe` — versioned per-user installer
- `GAM-Setup.exe` — stable installer filename used by installed-build updates
- `GAM-Portable-2.0.0.zip` — self-contained portable build
- `SHA256SUMS.txt` — SHA-256 checksums for the release files

The Setup and Portable packages are self-contained multi-file builds. Keep all
extracted files together. Neither a separate .NET runtime nor the Visual C++
Redistributable is installed by GAM.

## Known limitation

The executables are not Authenticode-signed. Windows SmartScreen can display a
warning; compare the downloaded file against `SHA256SUMS.txt`. A final clean
Windows-machine smoke test is still recommended before changing repository
visibility or announcing the build publicly.

This private validation build consolidates the previous private `2.0.0`,
`2.0.1`, `2.1.0`, and `2.2.0` builds under the `v2.0.0` version number. None of
those builds can detect the rebuilt package as a newer automatic update: it is
either the same version or a SemVer downgrade. Uninstall the old GAM entry from
Windows Settings and install this rebuilt package manually once. Portable users
must close GAM, extract the new ZIP, and manually replace the old Portable
folder. The uninstaller leaves the configuration under
`%APPDATA%\GmodAddonManager` intact. Later versions can resume normal
version-based update checks.

Standalone or portable v1 copies have no uninstall registration and cannot be
detected reliably by Setup. Remove those old folders manually and do not launch
their executable after migrating to v2.

## Configuration migration and downgrade

The first launch migrates older profiles to configuration schema 7. Assets,
subscription history, `GMod Disabled Addons`, observed GAM/GMod baselines,
pending-write journals, and image references are preserved. Before changing an
older profile, GAM keeps the original file as
`%APPDATA%\GmodAddonManager\config.json.pre-schema-7.bak`.

Older GAM versions cannot safely open a schema 7 profile. To downgrade, close
both GAM and GMod, preserve the current configuration separately, and restore
the pre-schema backup as `config.json`. Do not launch an old v1 executable after
v2 migration: it can recreate the legacy physical Workshop layout.
