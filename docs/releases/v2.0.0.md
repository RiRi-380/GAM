# GAM v2.0.0

GAM 2.0.0 is the consolidated v2 baseline. This replacement release combines
all product changes developed across v2.0.0 through v2.0.4 with the
latest Asset creation, Addon details, sharing-preference, licensing, and
packaging corrections.

## Asset and profile management

- Asset Groups can contain Assets and nested Asset Groups. Group state is
  inherited by newly created children, and hierarchy depth remains bounded by
  the configured limit.
- Custom Assets and Asset Groups can be reordered directly by pressing and
  dragging their cards. `Subscribe Asset` and `GMod Disabled Addons` remain
  fixed, while favorite and normal entries stay inside their own sections.
- The Asset destination picker follows the same hierarchy as the main Asset
  list instead of flattening every nested Asset into one long list.
- Smart Assets derive membership from GAM's inferred addon type and Workshop
  tag metadata and refresh on startup or manual refresh.
- `Subscribe Asset` and `GMod Disabled Addons` are fixed system Assets. Newly
  discovered subscriptions inherit the current Subscribe Asset state, while
  addons disabled in GMod remain represented separately.
- `.gam` Bundle v4 can preserve multiple Assets, nested groups, states, memos,
  and optional compressed images without changing Steam subscriptions.

## Interaction and UI corrections

- Creating an Asset Group stays in the current location and asks before
  opening the new Group. Existing Assets can be moved into a Group through its
  structure editor.
- Asset Group details and member configuration use two exclusive pages in the
  same window. Back and Escape discard temporary member changes; Apply keeps
  them pending until the Group details are saved.
- Switching the New Asset dialog from Asset Group back to Asset now resets the
  actual creation target and its form, preventing an Asset request from being
  created with the previous Group settings.
- Creating an Asset from selected Addons reports duplicate names and creation
  failures instead of failing silently.
- The Addon details surface has a visible, draggable vertical scrollbar and
  correctly handles wheel input over both the panel and its overlay.
- The choices to include images and memos in `.gam` sharing are saved when
  changed and reused the next time sharing is opened. Both remain off for new
  or legacy settings until the user enables them.
- Addon images, Workshop names, subscription timestamps, chronological
  sorting, split-window layouts, and Asset Group navigation have been corrected
  and polished. Experimental local-addon display and Asset history remain off
  by default.

## Updater and installer reliability

- The installed-build updater waits for Setup itself rather than the entire
  relaunched process tree. The verified package and hidden launcher can
  therefore delete themselves after Setup finishes while the updated GAM stays
  open.
- Update downloads require HTTPS, an expected GitHub asset origin when
  credentials are used, a bounded response and download size, and a matching
  GitHub SHA-256 asset digest.
- Registered GAM v1 Setup installations update in place from either GAM's
  notification or a directly launched v2 Setup. The installation directory and
  current-user or all-users mode are preserved, and elevation is requested only
  when the existing all-users installation requires it.
- Setup no longer downloads or launches the unnecessary Visual C++
  Redistributable. Managed upgrades delete only obsolete files listed by the
  previous release manifest. The two historical Steamworks helper files are
  removed during v1 migration only when both size and SHA-256 match known GAM
  payloads; unknown same-name files are preserved.
- Portable builds carry a portable-only marker and never install a second
  registered copy while updating.

## Reliability, security, and licensing

- Legacy v1 hard-layout data is detected before normal startup and recovered
  through a journaled, validated migration path rather than deleting or
  overwriting Workshop payloads in place.
- Path-health migration accepts data only from the exact legacy GAM-managed
  root and revalidates every source and target before moving it. A damaged or
  edited configuration cannot nominate a Steam Workshop or GMod payload root
  as GAM-managed data.
- `.gam` archives and `addon.json` metadata have technical resource bounds,
  path validation, cancellation support, and fail-closed malformed-input
  handling.
- Standard GMA v0-v3 headers and numbered file tables are parsed according to
  the official `gmad` layout, including required-content lists and
  classification metadata stored in the header description.
- Deferred GMod runtime changes are persisted even when startup discovers a
  membership change before the runtime queue has finished initializing.
- GitHub Actions are pinned to reviewed commit SHAs, NuGet restore uses checked
  lock files and fails on vulnerability advisories, and release tags must be
  annotated exact SemVer tags pointing at `origin/main`.
- The repository and distributed packages use the unmodified standard GNU GPL
  version 3 text in `LICENSE`; GAM's product and copyright attribution is kept
  separately in `NOTICE`. Both files are included in packaged distributions.

User data under `%APPDATA%`, GMod settings, Workshop payloads, and Steam
subscriptions are never deleted or moved by Setup.

## Updating from earlier builds

Registered GAM v1 users can upgrade normally through GAM's update notification
or by launching this Setup directly. Setup upgrades the registered copy in
place, closes the old process, and starts v2 after a successful installation.

This release replaces the previously published `v2.0.0`, `v2.0.1`, `v2.0.3`,
and `v2.0.4` packages under the `v2.0.0` version number. An already installed
v2 build cannot detect the replacement as a newer automatic update: it is the
same version or a SemVer downgrade.
Existing v2 Setup users must download and run
this replacement Setup manually once; a prior uninstall is not required.
Portable v2 users must close GAM, extract the new ZIP, and replace their old
Portable folder manually. Setup leaves the configuration under
`%APPDATA%\GmodAddonManager` intact. Later releases can resume normal
version-based update checks.

Standalone or portable v1 copies have no uninstall registration and cannot be
detected reliably by Setup. Remove those old folders manually and do not launch
their executable after migrating to v2.

## Files

- `GAM-Setup-2.0.0.exe` - versioned installer
- `GAM-Setup.exe` - stable installer filename used by installed-build updates
- `GAM-Portable-2.0.0.zip` - self-contained portable build
- `GAM-UpdateManifest-2.0.0.json` and `.sig` - signed compatibility metadata
  required by GAM v1.0.3-v1.0.5 update clients
- `SHA256SUMS.txt` - SHA-256 checksums for every release file

Setup and Portable packages are self-contained Windows x64 multi-file builds.
Keep all extracted files together. Neither a separate .NET runtime nor the
Visual C++ Redistributable is installed by GAM.

## Configuration migration and downgrade

The first launch migrates older profiles to configuration schema 7. Assets,
subscription history, `GMod Disabled Addons`, observed GAM and GMod baselines,
pending-write journals, and image references are preserved. Before changing an
older profile, GAM keeps the original file as
`%APPDATA%\GmodAddonManager\config.json.pre-schema-7.bak`.

Older GAM versions cannot safely open a schema 7 profile. To downgrade, close
both GAM and GMod, preserve the current configuration separately, and restore
the pre-schema backup as `config.json`. Do not launch an old v1 executable after
v2 migration because it can recreate the legacy physical Workshop layout.

## Known limitation

The executables are not Authenticode-signed. Windows SmartScreen can display a
warning; compare the downloaded file against `SHA256SUMS.txt`.
