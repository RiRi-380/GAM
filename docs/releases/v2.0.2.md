# GAM v2.0.2

GAM 2.0.2 is a small updater reliability release. It includes every change in
2.0.1 and does not change the configuration or `.gam` schema.

## Changes

- The installed-build updater now waits for the Setup process itself instead
  of the entire process tree. This lets the verified update package and hidden
  launcher delete themselves immediately after Setup finishes, while the newly
  updated GAM remains open.
- The updater still checks the Setup exit code, records installer failures,
  verifies the GitHub SHA-256 asset digest before launch, upgrades in place,
  and relaunches GAM.
- A process-level regression test now proves that a long-running relaunched
  child does not delay package or launcher cleanup.
- The public updater E2E now verifies the historical 2.0.0 path accurately:
  update and stable relaunch first, then eventual legacy-launcher cleanup after
  the updated application exits.

## Updating

Installed GAM 2.0.0 and 2.0.1 builds can detect 2.0.2 through GAM's update
check. The first update is initiated by the older updater, so its temporary
Setup and hidden launcher can remain until that newly opened GAM is closed
once. GAM 2.0.2 contains the fix; updates initiated by 2.0.2 and later clean
those temporary files immediately after Setup exits.

The installation directory and current-user or all-users mode are preserved.
The update does not remove or move `%APPDATA%\GmodAddonManager`, GMod settings,
Workshop payloads, Steam subscriptions, Asset Groups, or `.gam` data.

Portable builds receive the Portable ZIP and still require manual extraction;
they do not install a second registered copy.

## Files

- `GAM-Setup-2.0.2.exe` - versioned installer
- `GAM-Setup.exe` - stable installer filename used by installed-build updates
- `GAM-Portable-2.0.2.zip` - self-contained portable build
- `GAM-UpdateManifest-2.0.2.json` and `.sig` - signed compatibility metadata
  for legacy GAM v1.0.3-v1.0.5 update clients
- `SHA256SUMS.txt` - SHA-256 checksums for all release files

Setup and Portable packages are self-contained Windows x64 builds. A separate
.NET runtime or Visual C++ Redistributable is not required. The executables are
not Authenticode-signed, so Windows SmartScreen may show a warning; the release
checksums can be used to verify a download manually.
